POUR SOCIAL SCORE - VERSION HISTORY
(newest first)

=> 2.0.38 - Fix: frame jitter from background memory cleanup

- Fixed: frame jitter since 2.0.37. The background memory cleanup ran a full collection of the game's whole Lua memory (every addon, not just this one) at least once a minute. Each run costs one long frame wherever another addon holds a big table (measured 9 ms on a 150 MB heap and 19 ms on 300 MB) plus a few seconds of frames about 1 ms slower.
- The cleanup runs after something that leaves garbage behind (logging in, a /who scan, an import, closing the window) and otherwise every 10 minutes, as before 2.0.37. It no longer runs when the shared memory grows or every time the block log is trimmed. The game's own collector keeps running in the background every frame, as it always has.
- The cleanup never runs in combat, within 5 minutes of leaving combat, or inside a dungeon, raid, battleground or arena (the game reports which kind of instance you are in, so there is no list of places). A cleanup that was due waits until you are out.
- Chat filters are about a third faster per chat line (about 48 to 30 microseconds with 18 filters on) and leave about 20 % less garbage: each filter is turned into a function once instead of being walked as a tree for every line, the "is this a guild rule" check is worked out once per filter, and [word=...] skips building the word list when the word is not in the line at all. Results are unchanged (checked on 96,000 filter tests).
- Lua has no regular expressions, only Lua patterns. Measured: a pattern find of plain text is the same speed as a plain find, and patterns have no "a or b", so the filters keep plain finds.
- Version 2.0.38.

=> 2.0.37 - Per-player block history

- Block history stays one shared log of the last 2,000 lines (Options setting unchanged). In addition, every player on the Player Ignore List and every guild member keeps their newest 10 chat lines, 5 emotes, 5 party invites and 5 guild invites when their lines leave the log. A player's Block History shows those together with any of their lines still in the log.
- A line is in one place only: when it leaves the log it is moved to the person's keep (PourSocialScoreDB.blockKeep), never copied. Block counts (session, last 24 hours and total) are kept on each person and filter as before and are never worked out from history lines, so nothing is counted twice. Chat filter lines are not kept per sender.
- Upgrade: on the first login the log is trimmed to the setting and the lines it drops go to their person's keep. Saves from before 2.0.17 (one list per person) are merged into the log first, so their older lines are kept too. Lines older versions already dropped cannot be brought back. Tested by loading saves from 2.0.1, 2.0.8, 2.0.17, 2.0.18, 2.0.19, 2.0.22, 2.0.35 and 2.0.36, each also with more history than the log holds (sh tools/harness/validate_all.sh).
- Tidy-up after the upgrade, on every login: block history lines of players no longer on the Player Ignore List, of guild members in no guild rule whose rule was removed, and of chat filters that no longer exist (such as retired built-in filters) are removed; rule tags of removed rules are cleared. Counts are not changed.
- Background memory cleanup runs at least once a minute (was every 10 minutes), still only out of combat and in small steps. Right after login the addon briefly shows about twice its real size: loading leaves about 4 MB of temporary data that the first cleanup frees.
- /pss mem shows how many lines are kept per person.
- Version 2.0.37.

Each line has the same per-type breakdown, in columns that line up. Total is the count shown before.
- This session counts from login or /reload. Last 24 hours is saved as one small table per hour that had a block (at most 24 per tab, older hours dropped), so it costs almost no memory.

Every saved total is kept as it was. Tested by loading saves from 2.0.1, 2.0.8, 2.0.17, 2.0.18, 2.0.19, 2.0.22 and 2.0.35 (sh tools/harness/validate_all.sh).

- New /pss mem [full]: addon memory (game figure, not measured in combat), game Lua heap, block history lines / cap and estimated size split by players / guild members / filters, list sizes, the shipped guild index and its records in use, chat filters, and the memory cleanup state. => 2.0.15 - Performance and memory pass

Measured in an offline test harness (same code, simulated client):
  chat line with all text filters on    ~520 us / 20.8 KB garbage  ->  ~37 us / 2.1 KB
  same line in each extra chat window    ~173 us /  6.5 KB         ->  ~11 us / 0.6 KB
  Group Finder row check (300 players)   ~690 us                    ->  ~19 us
  mouseover / nameplate of a player       ~60 us                    ->  ~16 us, and at most once per player every 2 minutes, never in combat
Results are unchanged: the new filter engine was compared with the old one on 40,000 random filters / lines with no difference.

- Chat filters are compiled once and cached; each line is analysed once and only when a text filter is on. When no text filter or flood filter is on, lines aren't even lower-cased. The flood filter is a ring + set instead of a list search. The sender's display name is only built for a hidden line.
- Core chat filter: the decision cache is keyed by the line ID number in a fixed 256-slot ring (no string per chat window); one context table is reused; debug messages are no longer formatted for every line while debug is off; the GUID cache is capped at 1,500.
- Player list lookups (chat, Group Finder rows and menus, the group warning) use the O(1) index instead of rebuilding the key of every list entry per call; the index and the guild member index are rebuilt only when something changed (they were also rebuilt every 30 / 60 seconds).
- Group roster changes are handled once, 1-2 s after a burst, and not in combat. Unit scanning (target, mouseover, nameplates, group) does nothing in combat and looks at each player at most once every 2 minutes.
- Managed guild lists: the member index is built in the background in 0.5 ms slices per frame, paused in combat (a 50,000-name list indexes in ~300 frames with no hitch); the index keeps one number per member, not another copy of each name; member counts are worked out arithmetically; records for shipped members are freed when unused (changed ones are kept until saved); seeing a shipped member in the world no longer creates a stored record.
- Guild records are no longer recounted on every scan result / unit seen. Filter block history is checked for the old format once per session instead of on every blocked line. The duplicate list of each player's last 10 whispers (also in the block history) is no longer kept.
- Name formatting (Proper / strDown) rewritten without per-character string building (identical output on 30,000 random names).
- New PSS_Perf.lua - memory cleanup: never a full collectgarbage("collect"); small incremental steps (8 KB) within a 1 ms-per-frame budget (5 % of a slow frame), only out of combat, outside encounters, alive and above 30 fps, stopping the moment combat starts and resuming after it. Runs after /who results, imports, closing the window, building the shipped guild index, at login, when the Lua heap grew by 8 MB, and every 10 minutes. Option: "Background memory cleanup (out of combat, never causes a hitch)" (on). /pssguild status shows it.
- Version 2.0.15.

=> 2.0.0 - One chat-block core

File layout
- PSS_ChatBlock.lua      The single chat-block function. Every chat line, invite, duel and trade goes through it.
- PSS_PlayerIgnoreList.lua  Player Ignore List logic (list, sync, /pss, per-player switches) + its block source.
- PSS_GuildIgnoreList.lua   Guild Ignore List logic (rules, members, scans, /pssguild) + its block source.
- PSS_ChatFilters.lua    Chat filter rules and the filter engine, registered with the core as its text check.
- PSS_Options.lua        Options registry, the Options tab, and the scoped option resolver.
- PSS_ImportExport.lua   Import/Export tab and the export string format.

How a chat line is decided (OlympusMute model)
1. One filter on every chat event; the decision is cached per line, so a line shown in 5 chat windows is decided and counted once.
2. System lines (ignore-list sync noise, logins of listed players) and NPC lines are checked first.
3. People: the sender is looked up once (GUID first, then a normalised name key) in BOTH lists. The lists are merged:
   if ANY list blocks that message type for that person, the line is hidden. Lookups are hash-table (O(1)),
   so list size does not matter (tested: 20,000 guild members + 3,000 players, ~55 microseconds per line).
4. Ignored servers.
5. Chat filters (text rules) last. Staff (GM/DEV) messages are never text-filtered. You and your own messages are never blocked.
When a person becomes blocked, their earlier lines are removed from the chat windows, and a party invite from them that is still open is declined.

Per-person message types (the same on both lists)
- Whispers, Party invites, Guild invites, Party/Raid chat (includes raid warnings, instance chat); world chat is always blocked.
- Player Ignore List: switches W / I / G / P on each row.  Guild Ignore List: guild columns + per-member Allow columns
  (new "Allow Guild Invites" column; older saves copy the Group Invites setting).

Options
- Every option has a value for all characters, plus an optional override for the current character (Options tab, right column).
- Options marked * can also be set per guild (right-click a guild row) and per person (right-click a player row or a guild member):
  Send ignore response, Show declines, Decline duels, Decline trades.  Most specific wins: person > guild > character > all characters.

Import/Export (tab between Chat Filters and Options)
- Export any of: Player Ignore List (with switches, notes, overrides), Guild Ignore List (optionally with captured members),
  custom chat filters, built-in filter on/off, options.  Import with Merge (adds what is missing) or Replace (with confirmation).
- The string is "PSS1:<checksum>:<data>". It is read as data only (never run as code) and is rejected if damaged or edited.

Behaviour changes to know about
- CHAT_MSG_COMMUNITIES_CHANNEL is now covered as world chat.
- Your own outgoing whispers are no longer hidden.
- Duels and trades are now also declined from guild-list members (both can be turned off, also per guild/person).
- The "Add Player" button now works (it called a missing function before).
- Chat bubbles are not filtered.

=> 6.1.3

An "Ignore" option is now added to the targeted player menu while in a Raid group

An "Ignore" option is now added to the targeted player menu while in a party

PSS now has an automated expiration system which allows players to be automatically removed after a specified number of days.  This can be set using the UI or chat commands, and a default value for all newly added ignored players can be set too!

"/pss defexpire days" can now be used to set the number of days that newly ignored players will remain on the list before they are automatically removed.

"/pss expire character days" sets the number of days in which the character should remain on the list.  So for example "/pss expire mytoon 30" will set character mytoon to be automatically removed after being on the list for 30 days.

Right clicking in the ignore tab UI now brings up a drop down menu that allows the note to be edited, the expiration days to be set, or the person to be removed from the list.  Double clicking still provides a quick way to set their note.

The /ignore and /pss add commands now allow a note and expiration days to be supplied.  A simple /ignore works as it always has, but now you can also supply the days after the name followed by a note.  Here are some examples:

	"/ignore mytoon" This will ignore mytoon with the default configured expiration time
	"/ignore mytoon 30" This will ignore mytoon with a 30 day expiration time
	"/ignore mytoon this person is mean!"  This will ignore mytoon and set their note to "This person is mean!"
	"/ignore mytoon 30 this person is mean!" This will ignore mytoon, removing them after 30 days, and setting their note to "this person is mean"

PSS has now been tested and fixed to work with multiple language character sets and unicode/high ASCII characters!
