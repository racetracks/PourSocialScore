# Operating Core
Loaded by every agent: every line here is paid on every spawn. Keep it lean.
- Coordinator (main thread): also read `.claude/roles/coordinator.md` once per session.
- Consultant / engineer / engineer-m1 / engineer-m3: your rules are in `.claude/agents/<role>.md`.
- Session paths are relative to the session directory named in `.claude/.session` (created by hook; override with env `SESSION_DIR`).

## 0. Precedence
Token minimisation governs every choice. Only these outrank it:
1. Correctness of the delivered work.
2. Mandatory deliverables and completion criteria in `TASK.md`.
3. Role boundaries (§2) and budgets (§4). They exist to minimise tokens and are never traded for convenience.

Everything else (records, reports, visuals, document formats) is produced by script or hook, or scales down with the task, unless `TASK.md` mandates it. Between correct options, take the cheaper; when unsure, the one that writes less.

## Token rules (all roles)
Source: `CLAUDE.md`, loaded by every agent; agent files hold no copy (`.claude/scripts/sync-token-rules.py --check`).
Output tokens are the main cost, fresh reads the next. Every rule caps one or both.
- **Context:** your prompt and brief are your whole context. Read only what they name. Before reading, check what is already captured (`STATE.md`, `context/<stream>.md`, existing outputs); never regenerate or re-read it. Missing input → return `BLOCKED`/`NEEDS`; never explore.
- **Budget:** two ceilings, `calls` (tool calls) and `out` (lines you write: files, edits, messages; lines a script generates do not count). Take the cheapest correct path; a ceiling is not a target. At either ceiling stop and return `BUDGET`.
- **Pointers, not payloads:** refer to `path:line-range` or `path#anchor`. Never copy source, specs, diffs or tool output into briefs, reports or messages.
- **Read:** clone or pull each repo once per session; read from the local checkout, never the web. Grep/Glob, line ranges, `head`/`tail`, `--stat`/`--name-only` before opening. Whole files only when marked **Full**. Never re-read an unchanged file.
- **Tool output:** summarise large output to the essentials immediately; never carry raw dumps forward. Run independent tool calls in parallel, in one turn.
- **Resume:** after a restart or compaction, resume from your `STATE.md` (agents) or `CONTEXT.md` + `ledger.py next` (coordinator); re-read sources only for what those lack.
- **Commands:** quiet flags, filters, failure-only test output; on CI failure read only the failing job's log tail. Validate cheaply (dry-run, lint, small sample) before expensive steps; on a blocking error stop and report. Allocate all identifiers/keys in one batch, at planning time.
- **Write:** targeted edits, never a whole-file rewrite for a small change. Anything repetitive, structural or derivable (skeletons, tables, indexes, file maps, reports from JSON/YAML) is generated by script. Each fact once; link elsewhere.
- **Reason:** plan once; no narration, alternatives, polish or extras; stop when acceptance is met; diagnose from the error before retrying, never blind-retry.
- **Agent-ready output** (`DEC-00384`): every document you create or update (doc, plan, brief, spec, context, report, artefact) is shaped for the cheapest agent that reads it next, within that agent's budget: a header line first (purpose · owner · status · related); stable `##`/`###` anchors, so a reader takes one section, never the whole file; each section self-contained and inside the caps of `.claude/agents/consultant.md#context-caps`; tables, schemas and pointers before prose; current truth only (history in the Changelog or the build history). **Code is not capped; every code change updates its documentation in the same delivery** (the docs its brief names: the code map, the feature's documents, the build history's `Docs updated:` line), written to the same standard, pointing to the code by `path:line`. `python3 .claude/scripts/check_context.py <files>` checks both: the ledger on every return (`SHAPE`, `DOCS`), the rules check on every PR.
- **Return:** ≤5 lines per core §3. No greetings, restatements, progress or offers.

## 2. Roles
| Role | Model | Produces | Never |
|---|---|---|---|
| Coordinator (main thread) | session model, never switched | routing, ledger commands, user replies | read source/code/specs; design; write code, tests, scripts, specs or briefs |
| Consultant | large | decisions and engineer context: `provision.md`, specs, briefs, `context/`, answers, reviews | write code, tests, scripts or config of any size; run commands; spawn |
| Engineer | sonnet, lowest effort | all code, tests, scripts, bulk edits, generated docs, from a brief | design, guess, edit specs/briefs, spawn |
| Engineer-M1 | haiku, lowest effort | M1: exact edits or one script, from a brief | judgement, design, spawn |
| Engineer-M3 | large | one fenced, consultant-justified, judgement-bound change | anything outside its fence; tests, docs, mechanical follow-on |

Models are pinned in each agent file and fixed at spawn; an agent keeps its model for life.

**Production rule:** only engineers produce code, tests, scripts, config or bulk edits. M3 roles exist to make engineers reliable, not to do their work. A consultant decides, from context, which class and agent receive each task.

Classes (assigned by the consultant from scope and complexity, consultant K0): **M1** well scoped, deterministic (script first) · **M2** well scoped, judgement only where the brief lists it · **M3** open judgement, design, or not yet scoped.

## 3. Communication
- Only the coordinator spawns or continues agents. Work moves through files; prompts carry paths, never content.
- Every return is ≤5 lines: line 1 status, line 2 as below, line 3 `spend: calls a/b · out c/d` (since this spawn or continue).

| Status | Meaning | Line 2 |
|---|---|---|
| `DONE` | acceptance met | acceptance result + `agents/<id>/REPORT.md` |
| `BLOCKED` | needs a decision | `agents/<id>/QUESTIONS.md` |
| `NEEDS` | work or inputs outside scope | `agents/<id>/NEEDS.md` |
| `BUDGET` | a ceiling reached | `agents/<id>/STATE.md` |

## 4. Budgets
Every spawn and continue carries both ceilings, printed by the ledger in the spawn line. Defaults live in `.claude/agents/consultant.md#budgets`; anything above a default needs a one-line `Why` in `provision.md`. Budgets rise only through re-triage, never ad hoc. `ledger.py` validates provisioning, records spend, fences writes and triggers re-triage. Read cost is budgeted too: the startup files, each document kind and each section have caps; code has none, but every code change carries its documentation (`.claude/agents/consultant.md#context-caps`, `DEC-00385`), checked by `check_context.py`.

## 5. Layout (session directory)
| Path | Owner | Content |
|---|---|---|

| `briefs/<task>.md` | consultant | engineer brief |

| `prompts/` | hook | verbatim prompts + index |
| `README.md` | `ledger.py render` | session index + summary visuals |
