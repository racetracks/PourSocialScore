# PSS harness (tools/harness)
Purpose: PSS harness commands and checks · Owner: PSS pack · Status: current · Related: baseline 06, docs/pss/15_ROUTES.md

**The harness is the simulated client Claude codes against (required, the author, 2026-10-09; 11_PREFERENCES).** The general harness is baseline 06; this file lists PSS's commands and checks.

- **Client:** `wow_stub.lua` is the client (`PSS_FLAVOUR=retail|forever|tbc|era` picks the client, default retail; `PSS_CAMELOT=1` is its alias for `forever`, and with another `PSS_FLAVOUR` the stub fails to load; `PSS_STUB_PID`, `PSS_STUB_IFACE`, `PSS_STUB_NOCONST`, `PSS_STUB_OFF` override single values; `PSS_STUB_BLANK=1` makes `GetBuildInfo` return `""`, `" "`, `""` then the interface; `H.flavour` is the resolved name). `run.lua <addon dir> <save|-> <out|-> [script]` loads the addon folders, logs in, runs the script with `H` (the stub: `H.Fire` for events, `H.chat` for chat output, `H.Private` for a folder's private table) and `M` (the script's own; addon code sees no global `M`, as in game), logs out and writes the save. Slash commands and frame clicks are driven from the script; `tui_tour.lua` writes the window's frame dump to `PSS_UI_DUMP`.
- **Use it while writing a change:** a one-off script that drives the changed path and prints what happened is the first test; the lasting check that fails on `origin/main` is the second. What it cannot show (wrapped text, combat and chat lockdown timing, taint, real art) goes to the in-game checks.
- **Setup:** `lua5.1` (apt) and `git fetch --depth=2000 origin main:refs/remotes/origin/main`. The explicit ref matters: in a single-branch clone a plain `git fetch origin main` leaves `origin/main` unknown and the comparisons skip. The depth matters: `validate_all.sh`'s upgrade checks rebuild old versions from history, and in a shallow clone its "split" checks fail on 2.0.1 and 2.0.40.
- **Real saves** live only on scratch (`SavedVariables/<version>/` is client `forever`; `SavedVariables/<client>/<version>/` keeps its client, `retail forever tbc era mists`, any other is skipped with `skip <name>: unknown client`). `sh tools/harness/build_saves.sh <scratch checkout> [out dir]` writes `<out dir>/<client>/<version>/<save>/PourSocialScore.lua` (`tools/harness/build_saves.sh:43`: a version folder's own files are save `main`, each `<save>/` subfolder holding `PourSocialScore.lua` is save `<save>`, none overwritten) and prints first `install forever <folder>, retail <folder>: P1 shared` (`P1 separate` when the folders differ; read from `gen_toc.lua --install`), then `<client>/<version>/<save>: <n> bytes` for each; `validate_all.sh` runs each real save with `PSS_FLAVOUR` set to its client folder (`save_key`, `tools/harness/flavours.sh:6`, which also reads the old `<client>/<version>/` layout) (a 2.0 save as is; a 3.x set joined: core, Options, Logging, EllesmereUI; out dir defaults to `/tmp/pss-baselines`).
- **`validate_all.sh` switches:** `PSS_REAL_SAVES=<out dir>` adds every real save; a check that cannot run prints `SKIPPED ...` and fails the run (`PSS_ALLOW_SKIP=1` accepts it); `PSS_SAME_AS=<ref>` runs `same_saves.sh` at the end; `PSS_SPARSE_AS=<ref>` compares every save with another build through `sparse_saves.sh` (opt-in, for a change to the saved layout); `PSS_VALIDATION_LOG=<file>` also writes the whole output to that file (same output and exit status). The output is always kept in a log (`PSS_VALIDATION_LOG`, default `$TMPDIR/pss-validate-last.log`) and ends with a per-section table (PASS, FAIL, SKIP, seconds); every section closes with a `-- <s>s, total <s>s: <name>` line; `PSS_SECTION_TIMEOUT=<s>` (default 300, `0` off) fails and stops a section that runs longer (`validate_watchdog.sh`); without `PSS_SCRATCH` a scratch checkout at `../Pour-Social-Score_Scratch` is used.
- **Real-only mode (`PSS_REAL_ONLY=1`, with `PSS_REAL_SAVES`; the CI `real-saves` job):** `validate_all.sh` runs only the statements that read real saves; the kept sections are `real_section` (`tools/harness/validate_all.sh:68`), every other section prints `SKIP real-only: <section>` and its body does not run, and the synthetic lines inside a kept section are guarded by `full` (`tools/harness/validate_all.sh:75`). Without `PSS_REAL_SAVES` it prints `real-only needs PSS_REAL_SAVES` and exits 2 (`tools/harness/validate_all.sh:16`). `ix_phases.sh` and `console_phases.sh` with `PSS_REAL_ONLY=1` and no phase named run only their `REAL` phases on the saves, with no synthetic run (`tools/harness/ix_phases.sh:59`, `tools/harness/console_phases.sh:19`). The `upgrades` job runs the full harness (no `PSS_REAL_ONLY`).
- **Sharded real saves (the CI `real-saves` check, `.github/workflows/rules.yml:157`):** `real-saves-prep` builds the saves once per scratch commit (cache key `pss-saves-v1-<scratch sha>-<hash of build_saves.sh>`) and plans the shards; `real-saves-shard` runs each shard with `PSS_REAL_ONLY=1`; `real-saves` writes the shard summaries in order and fails when a shard failed. `sh tools/harness/shard_saves.sh plan <saves>` prints the shards JSON, `[0..K-1]`, K = 0 for no saves, else min(8, ceil(N / 6)) (`tools/harness/shard_saves.sh:13`); `sh tools/harness/shard_saves.sh link <saves> <k> <K> <out>` links shard k's saves at `<out>/<client>/<version>/<save>/PourSocialScore.lua`, dealt largest first in snake order (`tools/harness/shard_saves.sh:20`); exit 2 on bad arguments. `sh tools/harness/fail_summary.sh <k> <log>...` prints `### Real saves shard <k>: <p> PASS, <f> FAIL`, then per `<client>/<version>` a table of save, kind (text after `FAIL ` up to `:`) and count with the first 5 lines of each kind, and one `::error` line per group and kind on stderr; FAILs before any save path are group `synthetic`; exit 0 always (`tools/harness/fail_summary.sh:13`).
- **Stage close (`DEC-00390`):** `sh tools/stage_close.sh <scratch checkout> [--dry-run] [--no-host] [--no-push]`, run from the addon repo root; quiet, failure-only. Four steps in order, stopping at the first failure: `saves` (`build_saves.sh`), `validate` (`validate_all.sh` on those saves), `host` (`host_build.sh`, the test zip; skipped by `--no-host`, `--no-push` is passed on), `render` (`ledger.py render`, the session README). `PSS_STAGE_OUT` (default `${TMPDIR:-/tmp}/pss-stage-close`) is the out dir, removed and recreated at start; each step's full output is `<out>/<step>.log`. Exit 0 all passed (or a dry run, which prints `would run:` lines), 1 a step failed (`FAIL <step>` and the log tail), 2 a bad option, wrong directory or missing checkout.

Other checks in `validate_all.sh`: `check_forget` (removals), `check_guildrule`, `check_alerts`, `check_ondemand`, `check_gc` (event-driven GC, no timers), `check_capture` (P3: capture events only while they can be used), `check_recent`, `check_savedlog`, `check_growth`, `check_unitmenu` (B2), `check_fixes` (F1: N40 to N48), `check_ownguild`, `check_viewfns` and `check_w2b` (W2: view logic in Libraries), `check_communities`, `check_communities_seen`, `check_packed`, `check_saveddata`, `check_multi.sh`. Benchmarks: `bench_chatpath.lua` (P4, CPU and garbage per chat line), `bench_redraw.lua` (W4, per redraw with a tab open), `bench_recent.lua` (behind the 144-slot recent layout), `measure_sparse.lua` (S3 resident cost). Inspection: `show_totals.lua`, `dump_counts.lua`, `dump_view.lua`. Measured runs (`PSS_MEASURE`) pre-grow the core `M` table right after `PSS_Globals.lua` (1100 pad keys, `tools/harness/run.lua:181`), so no later file is charged for its rehash.

**Shipped lists (N3):** after any rebuild with `tools/PSS_BuildManaged.lua` (`--reindex`; it drops or converts surname-as-realm names against its `REALMS` table), run `check_packed`, `check_communities` and `check_communities_seen`, and `tui_compare.sh` (only the member counts should change). `validate_all.sh`'s split check runs the old 3.0.0-dev12 build, which still ships the pre-N3 lists, so it expects `membersShown` 196 lower, plus one for each member the save stores under a dropped name (`surname_stored.lua`). A rebuild that changes the lists again must update those expectations too.

**Stub notes:** `wow_stub.lua` has font objects with `GetFont` / `SetFont` (recorded), `GetShadowOffset` / `GetShadowColor`, `CreateFont`, `GetPoint`, `IsPlaying`, `GameFontDisable`, `ChatFontNormal`, and the parts of `ScrollFrameTemplate`, `InsetFrameTemplate`, `PanelTopTabButtonTemplate`. Widgets expose their Dark parts as `widget.pssParts` and the window its looks' art as `PSS_Window.art`, so checks reach them through frames (no test-only globals). Unknown `Set*`, `Scroll*` and similar calls return a no-op, so check a template part's type before indexing it. The stub answers `C_XMLUtil.GetTemplateInfo` per flavour and builds `PanelTopTabButtonTemplate` on tbc from TBC's `TabButtonTemplate` parts (TBC's template inherits it); check_tabs.lua (TST-00984) asserts the selected tab's art per flavour (3.8.0.141).

**PSS habits:** a check that needs Libraries calls `M.PSS_Need("Libraries")` first; read every diff line on a real save before claiming "intended only".

**Tests bundle** (not hosted unless the author asks; 11_PREFERENCES): `sh tools/host_tests.sh <scratch checkout> [--no-commit | --no-push] [--log <file>]` builds `PourSocialScore-<version>-tests-<YYYY-MM-DD-hh-mm>.zip` from HEAD (`tools/`, `versions.json`, `.github/workflows`, `README_TESTS.txt`, and the validation log with `--log`; never real saves) into scratch `releases/`, adding its name to the index's releases row only (not `latest/`; the addon zip never holds `tools/`).
