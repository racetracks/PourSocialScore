# PourSocialScore project instructions (paste into the Claude project)

You are working on PourSocialScore (PSS), Dan's WoW chat moderation addon. It follows the WoW addon baseline pack (rules, pipeline, staged delivery) and the scratch usage pack; this PSS pack adds and overrides for PSS. Read the baseline README, 02_RULES, 07 and 10, the scratch pack README, then this pack's 00_README and 06_STATUS_AND_NEXT before the first step.

Repos: racetracks/PourSocialScore (seven folders, one version) and racetracks/Pour-Social-Score_Scratch (hosting; scratch rules in docs/scratch/05_RULES.md). Never write to racetracks/PourSocialScore-EllesmereUI (retired). Read only: EllesmereGaming/EllesmereUI (all rights reserved), Gethe/wow-ui-source.

Clients: Retail 120007 and Camelot 16001, three TOCs per folder. Everything on M via PourSocialScore_NS; core fires M.Events; UIs write only through core setters. Tabs, except PourSocialScore_EllesmereUI (4 spaces).

Live release: 3.4.0.29 (the new PSS window, 2026-10-08; 3.3.1 before it). Next: the 3.4.1 line from build 30. Current feature: the new PSS window, version line 3.4.0, every build X.Y.Z.B and a pre-release, the release a build too (3.4.0.29) only when Dan says it is a release (docs/pss/02_RULES.md section 8, docs/pss/09_PSS_UI_PROJECT.md): one window in the EllesmereUI port's layout (the port is the reference; the old GUI is not authoritative), logic in PourSocialScore_Libraries, drawing in PourSocialScore_GUI (from 3.4.0.25; PourSocialScore_UI and PourSocialScore_EllesmereUI are gone), opened with /pss gui. The baseline's rules are mandatory; PSS overrides one only in docs/pss/02_RULES.md section 12. Versions X.Y.Z.B with a build number that never resets, a release too, recorded in versions.json (never shipped) via tools/bump_version.sh; a full release's notes are one summary of every change since the last release, written at release time from its PRs (CLAUDE.md); test zips via tools/host_build.sh. Three looks, listed in this order: Modern (the default), then the options Classic (was Blizzard) and Dark (the port's style); every element works in all three; accent always the class colour; only the main window's title carries the addon's name, popup titles say what they ask. The window's rules are the Interface section of CLAUDE.md. Project data on scratch: always read docs/latest/ first (docs/README.md).

PSS rules (02_RULES in the PSS pack):
- Core holds only the chat filtering engine and the launchpad; anything not regularly active, including code both UIs share, goes in PourSocialScore_Libraries, with a measured resident cost.
- No application or service logic in PourSocialScore_GUI or PourSocialScore_EllesmereUI. The native GUI never reads or loads a file from the EllesmereUI folder; the EUI folder is read only during parity work.
- Ports to native use only our own or Blizzard resources, look as close as possible to the EUI version, and may copy our own EUI code when it is smaller (never EllesmereUI's code).
- Every number the EUI window shows equals the native window's. Logging loads only when logs are called.
- Taint and secrets (baseline 02 J, PSS 02 section 10): never write or replace Blizzard state, post-hooks and Menu.ModifyMenu only; every chat, unit and hook value goes through M.PSS_IsSecret before any compare or index; a secret line is neither filtered nor counted; test chat and hook changes with addonChatRestrictionsForced and addonCombatRestrictionsForced.
- Never change TOC Title or Notes. SavedVariables layout changes need Dan's OK and a migration validated on the three real saves.
- Before pushing: sh tools/check_rules.sh, PSS_REAL_SAVES=<out dir> sh tools/harness/validate_all.sh (saves built from scratch SavedVariables/ with tools/harness/build_saves.sh; scratch is the project files, there is no /mnt/project-files), and tui_compare.sh (all three looks) for any change that should not show.
- Test zips on scratch releases/PourSocialScore-<version>-<YYYY-MM-DD-hh-mm>.zip plus the newest in latest/, linked as https://github.com/racetracks/Pour-Social-Score_Scratch/raw/main/<path>. Real saves in scratch SavedVariables/<version>/; never commit them to the addon repo.
- Dan tests in game and merges. Numbered questions with a recommendation; answer first; measure, don't estimate.
