# Closed project: the new PSS window (3.4.0, released 3.4.0.29)

One window with the EllesmereUI port's layout, features and feel, drawn only
with Blizzard's and our own resources, in three looks. It replaced both old
windows (the old native GUI and `PourSocialScore_EllesmereUI`) at the cutover
(D2, 3.4.0.25; read the old windows from git history, tag v3.4.0.24).
Started 2026-10-07, released 2026-10-08 as **3.4.0.29** (notes: one summary of
PRs #88 to #117).

**Rules:** the window's rules are the **Interface** section of `CLAUDE.md`
(the one place for them). This file holds the decisions behind them, the code
map and the lessons; it stays the reference for any window change. The full
code map is on scratch [`documents/code-map/`](https://github.com/racetracks/Pour-Social-Score_Scratch/tree/main/documents/code-map) ([`05_Detailed_Design.md`](https://github.com/racetracks/Pour-Social-Score_Scratch/blob/main/documents/code-map/05_Detailed_Design.md) section 9, [`14_04_GUI_API.md`](https://github.com/racetracks/Pour-Social-Score_Scratch/blob/main/documents/code-map/14_Code_Reference/14_04_GUI_API.md)).

**Project data on scratch:** the plan in `docs/latest/ui uplift/` (01_ANALYSIS,
02_PLAN, 03_CODE_CHANGES, 04_LOOK_SPEC: the look numbers); history in
`history/addon/2026-10-08-PourSocialScore_GUI-ui-uplift/`, zips `docs/ui-uplift-<date>-vN.zip`.

## The author's brief and decisions (2026-10-07)
1. Every element of the EllesmereUI port becomes native. No EllesmereUI dependency and no EllesmereUI names: PSS names only (`check_rules.sh` fails on `EUI` or `Ellesmere` in `PourSocialScore_GUI` and the Libraries view files `PSS_ViewNav`, `PSS_DetailQuery`, `PSS_PlayerView`, `PSS_GuildView`, `PSS_FilterView`, `PSS_EventsView`, `PSS_OptionsView`).
2. **The port is the reference for every visual and layout choice; the old GUI is not authoritative on anything.**
3. All logic (state, navigation, queries, shaping, validation, flows) in `PourSocialScore_Libraries`; drawing only in the window's folder, split by function. (Built in `PourSocialScore_UI`, moved into `PourSocialScore_GUI` at D2.)
4. The window took over `/pss gui`, the Friends / Social docking and the Addon Compartment at the cutover (D1). `/pss` on its own opens it; `gui`, `ui` and `eui` are aliases (the author, 2026-10-08).
5. **At the cutover the new files moved into `PourSocialScore_GUI`** (its Title and Notes kept); `PourSocialScore_UI` and `PourSocialScore_EllesmereUI` were deleted. Upgrade step 7 prunes `euiIntegration` and the old windows' sizes, widths and places.
6. **Three looks** (option `uiSkin`), same layout, features and feel in each. **Modern is the default** (the author, 2026-10-08); listed Modern, then Classic and Dark; the saved values stay 2, 0, 1:

   | Value | Name in Options | Look |
   | --- | --- | --- |
   | 2 | Modern (Default) | Blizzard's 12.x Social window (the author's /fstack screenshots, 2026-10-07): the metal frame (`UI-Frame-Metal` nine-slice) on black (the Social window sets its Bg to black); behind the tab row and the line under it the frame's stone (`UI-Background-Rock`) with its streaks (`_UI-Frame-TopTileStreaks`) over it, as the AddOns list draws its top (the streaks alone are a dark overlay and show nothing on black); in Classic and Modern the streaks reach down past the arrows' line to the pages (our own texture; the template's stop 43 px down); pages on the black under `perks-divider-short`; inset boxes as `friends-card-default`; buttons and tabs the straight gold-framed action button (`common-button-tertiary-normal`, `-pressed` while held, the same art on top for hover and a selected tab; the side-tab plate's cut corner looked uneven), the accepting button `128-RedButton` three-slice (compared in game against the Filter button art and kept, the author); `checkbox-minimal` / `checkmark-minimal`; `common-searchbar-a` boxes with `common-searchbar-icon-a`; popups in the window's own frame on black; drop-downs, menus and tooltips Blizzard's. Retail only; without the art it falls back to Classic |
   | 0 | Classic | Blizzard's classic templates (`ButtonFrameTemplate`, `UIPanelButtonTemplate`, `UICheckButtonTemplate`, `InputBoxTemplate`, `InsetFrameTemplate`, top tabs, `GameTooltip`); internal name "blizzard" |
   | 1 | Dark | The port's style in full (EllesmereUI's skin numbers): flat fills, one-pixel edges |

7. **Accent = your class colour, always, in every look; no option** (the author: "class colour is mandatory"). The look's own colour (gold; green for Dark) only if the client gives no class colour. `M.PSS_UIAccent` in Libraries.
8. **Font option `uiFont`**: the look's own (Blizzard's for Classic and Modern, Arial Narrow for Dark), or Game text, Unit names, Damage numbers, Friz Quadrata, Arial Narrow, Morpheus, Skurri, plus fonts other addons share through LibSharedMedia, **read only and only when another addon has loaded it** (the author's OK; 02 section 12, A10). PSS ships no library and never creates `LibStub`. Expressway (EllesmereUI's font) carries "Do not distribute" and is never shipped.
9. Old-GUI-only features were ported in the port's style: Player Search, add your target, Prune, right-click menus. Resizable columns and windows were dropped.
10. Popups: titles say what they ask, never the addon name; Dark draws the window's popups, tooltips and menus from our kit; Modern and Classic use GameTooltip and the Menu API, and the window's popups are our own frames in the window's own frame art (`ns.NewFrameArt`: Blizzard's dialog backgrounds were see-through; copy and import need a multi-line box, which StaticPopup lacks; no `StaticPopupDialogs` entry is written). Core's note, party warning and reload popups stay Blizzard StaticPopups (`CLAUDE.md` Interface, Titles and popups).
11. Window place, last tab and new settings live in `PSS_OptionsDB` (routed `PourSocialScoreDB` UI keys). No new SavedVariables.
12. Version line **3.4.0**; released as 3.4.0.29.

## Lessons
- **Blizzard tab labels:** `PanelTemplates_SelectTab` / `DeselectTab` re-anchor a top tab's label 4 / 8 px below centre (made for 32 px tabs), and the tab template's `OnShow` resizes the tab to its own padding (it cut "Player Ignore List" short). The kit drops those scripts on our own tabs and sets the label and the active art itself. A centring that those functions override does nothing: check what re-anchors a region before fixing its anchor.
- **Thin lines:** at UI scales under 1 a 1-unit line blurs and loses its colour. Lines and edges are one physical pixel (`ns.OnePixel`) with grid snapping off (`ns.NoSnap`).
- **Dimmed labels:** fade with `SetAlpha` (never text colour alpha, baseline 05 known fix 1); Dark's unselected tabs sit at 0.7, readable on the dark plate.
- **Template art across looks:** fade a template's textures with alpha and restore each one's own alpha, so the template's state changes cannot bring one back and Classic is exactly as Blizzard drew it.
- **Rotated art does not stretch along the other axis:** a tall side-tab atlas turned a quarter on a wide tab showed as thin strips. Keep frame art upright and stretch only its middle with slice margins, and match a look from the whole reference window (frame, background, panels, buttons), not from a few controls.
- **Frame art has its own levels:** `ButtonFrameTemplate`'s border (its NineSlice) sits at a fixed frame level of about 500, so a close button and title at the window's level + 8 were drawn under the metal edge. Anything that must show over a Blizzard frame template goes on a frame raised above the template's own parts. The same applied to the popups' titles, which now sit on a raised frame in the title bar in Classic and Modern.
- **`M.PSS_FindGuildRule` returns the key first, even when the rule is gone:** test its second value, `select(2, M.PSS_FindGuildRule(key))`.
- **Retail 12.x renamed the link insert:** Blizzard calls `ChatFrameUtil.InsertLink`; `ChatEdit_InsertLink` is only a deprecated copy (`Blizzard_DeprecatedChatInfo`, "removed at the next expansion"), so a post-hook on the old global never fires for Blizzard's own inserts. Hook the new name where it exists.
- **List cells are one line:** a font string given only a width wraps and spills over the rows below; row cells set `SetWordWrap(false)`, `SetMaxLines(1)` and the row's height, so long text ends in "...".
- **Blizzard's dialog backgrounds are see-through:** `DialogBorderTemplate` and the classic dialog backdrop let the window behind show through text. The popups use the window's own frame art (`ns.NewFrameArt`, shared with the window): the metal frame on its stone, or on black in Modern.
- **One Escape hides every shown frame in `UISpecialFrames`:** the window's Escape helper and a popup both went, so the window stepped back too. The helper asks `ns.EscapeTaken()` first. And **`SetScript` drops hooks**: a `HookScript` made before a frame's own `SetScript("OnHide")` never runs, so register after the scripts are set.
- **Blizzard's guild invite window is not a StaticPopup** (`Blizzard_FrameXML/GuildInviteFrame`): it opens with `StaticPopupSpecial_Show`, calls `DeclineGuild` itself in its `OnHide`, and hides on `GUILD_INVITE_CANCEL` or after 60 s. `StaticPopup_Hide("GUILD_INVITE")` does not close it.
- **A re-sort per blocked line is the hot spot:** `M.PSS_GuildRows` recounts every guild (`PSS_GetGuildBlockCounts` walks the members), 180 KB of garbage and 5 ms on the author's save. Count only what is drawn and leave the order to the next Resort. And the harness stub does not fire a child's `OnHide` when its parent hides, so the window calls each page's `release` itself rather than relying on it.
- **Ask which object a screenshot shows:** `/fstack` names only what is under the mouse; a screenshot of a highlighted region with an unrelated frame stack cannot be identified.
- **The console never loads Logging on show (3.8.0.121, C3):** first show runs the query with `load=false` (tier 1 shows Load history); Run, Enter, a left-list click and a deep dive run `load=true`. The console may be the restored tab, so show must stay free.
- **The search bar keeps its caret by drawing text at colour alpha 0 (3.8.0.121, C9):** the edit box text has alpha 0 and no shadow, and a coloured overlay draws the text; when the text is wider than the box the overlay hides and plain text shows. The one exception to "fade with SetAlpha" (02 section 11, waiting on the author's OK).
