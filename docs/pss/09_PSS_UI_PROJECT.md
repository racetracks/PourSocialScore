# Current project: the new PSS window (3.4.0)

One window with the EllesmereUI port's layout, features and feel, drawn only
with Blizzard's and our own resources, in three looks. It replaces both
`PourSocialScore_GUI` (old native window) and `PourSocialScore_EllesmereUI`
(the port). Started 2026-10-07. The live 3.3.1 release still ships both old
windows; their docs (01, 03, 08) stay true for it until the cutover.

**Project data on scratch (`racetracks/Pour-Social-Score_Scratch`), always
read the newest:** `docs/latest/` (the index, `docs/README.md`) holds the
newest markdown: the project plan (`docs/latest/ui uplift/`: 01_ANALYSIS,
02_PLAN, 03_CODE_CHANGES, 04_LOOK_SPEC) and these docs
(`docs/latest/pss-docs/`); history in `docs/ui uplift/`, zips
`docs/ui-uplift-<date>-vN.zip`. Test zips: `releases/` (dated) and
`latest/` (the newest). Real saves: `SavedVariables/<version>/`.

## Dan's brief and decisions (2026-10-07)
1. Every element of the EllesmereUI port becomes native. No EllesmereUI dependency and no EllesmereUI names: PSS names only (`check_rules.sh` fails on `EUI` or `Ellesmere` in `PourSocialScore_UI` and the Libraries view files `PSS_ViewNav`, `PSS_DetailQuery`, `PSS_PlayerView`, `PSS_GuildView`, `PSS_FilterView`, `PSS_EventsView`, `PSS_OptionsView`).
2. **The port is the reference for every visual and layout choice; the old GUI is not authoritative on anything.**
3. All logic (state, navigation, queries, shaping, validation, flows) in `PourSocialScore_Libraries`; drawing only in the new `PourSocialScore_UI` ("PourSocialScore UI"), split by function. Folder name `PourSocialScore_UI`.
4. `/pss tui` (temp UI) opens it while it is built; at the cutover it takes over `/pss gui`, the Friends / Social docking and the Addon Compartment.
5. **At the cutover the new files move into `PourSocialScore_GUI`** (its Title and Notes stay), replacing the old GUI's files; `PourSocialScore_UI` then goes away and only `PourSocialScore_EllesmereUI` is deleted.
6. **Three looks** (option `uiSkin`), same layout, features and feel in each. **Modern is the default from dev008_4** (Dan, 2026-10-08), and the Blizzard look is named Classic:

   | Value | Name in Options | Look | Built |

   | 2 | Modern (Default) | Blizzard's new 12.x Social window (Dan's /fstack screenshots, 2026-10-07): the same metal frame (`UI-Frame-Metal` nine-slice) on black (the Social window sets its Bg to black), behind the tab row and the line under it the frame's stone (`UI-Background-Rock`) with its streaks (`_UI-Frame-TopTileStreaks`) over it, as the AddOns list draws its top (Dan, dev008_3; the streaks alone are a dark overlay and show nothing on black); in Classic and Modern the streaks reach down past the arrows' line to the pages (dev008_4, our own texture; the template's stop 43 px down); pages on the black under `perks-divider-short`; inset boxes as `friends-card-default`; buttons and tabs the straight gold-framed action button (`common-button-tertiary-normal`, `-pressed` while held, the same art added on top for hover and a selected tab; dev004_3, after the side-tab plate's cut corner looked uneven), the accepting button `128-RedButton` three-slice; compared in game against the Filter button art and kept (Dan, dev004_4); `checkbox-minimal` / `checkmark-minimal`; `common-searchbar-a` boxes with `common-searchbar-icon-a`; popups in the window's own frame on black (dev011_3; `DialogBorderTemplate` until dev011_2); drop-downs, menus and tooltips Blizzard's. 7. **Accent = your class colour, always, in every look; no option** (Dan: "class colour is mandatory"). The look's own colour (gold; green for Dark) only if the client gives no class colour. `M.PSS_UIAccent` in Libraries.
8. **Font option `uiFont`**, both looks: the look's own (Blizzard's for Blizzard and Modern, Arial Narrow for Dark), or Game text, Unit names, Damage numbers, Friz Quadrata, Arial Narrow, Morpheus, Skurri, plus fonts other addons share through LibSharedMedia, **read only and only when another addon has loaded it** (Dan's OK for reading it). PSS ships no library and never creates `LibStub`. Expressway (EllesmereUI's font) carries "Do not distribute" and is never shipped.
9. Old-GUI-only features are ported in the port's style before the cutover: Player Search, add your target, Prune, right-click menus. Resizable columns and windows are dropped.
10. Popups (titles: what the popup asks, never the addon name, e.g. "Remove Player?", "Remove Guild?", "Remove Rule?"; Dan, 2026-10-08): in Dark everything comes from our kit (window popups, tooltips, menus, and core's note, party warning and reload popups); Blizzard uses GameTooltip and the Menu API, and the window's popups are our own frames in the window's own frame and background (`ns.NewFrameArt`; Dan, dev011_3: Blizzard's dialog backgrounds were see-through; dev003: copy and import need a multi-line box, which StaticPopup lacks, and no `StaticPopupDialogs` entry is written). Core's StaticPopups stay as they are.
11. Window place, last tab and new settings live in the Options addon's SavedVariables (`PSS_OptionsDB`, through the routed `PourSocialScoreDB` UI keys). No new SavedVariables.
12. Version line **3.4.0**. Until dev012 the stages were `3.4.0-devNNN` with fixes as `_N`; from 2026-10-08 every build is `3.4.0.B`, the next build number for each test zip, a stage or a fix (02 section 8), starting at `3.4.0.13`. All are pre-releases; plain `3.4.0` when Dan says it is done.

## Lessons so far
- **Blizzard tab labels:** `PanelTemplates_SelectTab` / `DeselectTab` re-anchor a top tab's label 4 / 8 px below centre (made for 32 px tabs), and the tab template's `OnShow` resizes the tab to its own padding (it cut "Player Ignore List" short). The kit drops those scripts on our own tabs and sets the label and the active art itself. A centring that those functions override does nothing: check what re-anchors a region before fixing its anchor.
- **Thin lines:** at UI scales under 1 a 1-unit line blurs and loses its colour. Lines and edges are one physical pixel (`ns.OnePixel`) with grid snapping off (`ns.NoSnap`).
- **Dimmed labels:** fade with `SetAlpha` (never text colour alpha, baseline 05 known fix 1); Dark's unselected tabs sit at 0.7, readable on the dark plate.
- **Template art across looks:** fade a template's textures with alpha and restore each one's own alpha, so the template's state changes cannot bring one back and the Blizzard look is exactly as Blizzard drew it.
- **Rotated art does not stretch along the other axis** (dev004): a tall side-tab atlas turned a quarter on a wide tab showed as thin strips. Keep frame art upright and stretch only its middle with slice margins, and match a look from the whole reference window (frame, background, panels, buttons), not from a few controls.
- **Frame art has its own levels** (dev007): `ButtonFrameTemplate`'s border (its NineSlice) sits at a fixed frame level of about 500, so our close button and title at the window's level + 8 were drawn under the metal edge. Anything that must show over a Blizzard frame template goes on a frame raised above the template's own parts.
- **`M.PSS_FindGuildRule` returns the key first, even when the rule is gone** (dev009): test its second value, `select(2, M.PSS_FindGuildRule(key))`.
- **Retail 12.x renamed the link insert** (dev010): Blizzard calls `ChatFrameUtil.InsertLink`; `ChatEdit_InsertLink` is only a deprecated copy (`Blizzard_DeprecatedChatInfo`, "removed at the next expansion"), so a post-hook on the old global never fires for Blizzard's own inserts. The EllesmereUI window still hooks the old name (its link converter's shift-click is likely dead on Retail; not changed, it is deleted at the cutover).
- **List cells are one line** (dev010_2): a font string given only a width wraps and spills over the rows below; row cells set `SetWordWrap(false)`, `SetMaxLines(1)` and the row's height, so long text ends in "...".
- **Blizzard's dialog backgrounds are see-through** (dev011_2, _3): `DialogBorderTemplate` and the classic dialog backdrop let the window behind show through text. The popups now use the window's own frame art (`ns.NewFrameArt`, shared with the window): the metal frame on its stone, or on black in Modern.
- **One Escape hides every shown frame in `UISpecialFrames`** (3.4.0.14): the window's Escape helper and a popup both went, so the window stepped back too. The helper now asks `ns.EscapeTaken()` first. And **`SetScript` drops hooks**: a `HookScript` made before a frame's own `SetScript("OnHide")` never runs, so register after the scripts are set.
- **Blizzard's guild invite window is not a StaticPopup** (3.4.0.14, `Blizzard_FrameXML/GuildInviteFrame`): it opens with `StaticPopupSpecial_Show`, calls `DeclineGuild` itself in its `OnHide`, and hides on `GUILD_INVITE_CANCEL` or after 60 s. `StaticPopup_Hide("GUILD_INVITE")` does not close it.
- **A re-sort per blocked line is the hot spot** (3.4.0.15): `M.PSS_GuildRows` recounts every guild (`PSS_GetGuildBlockCounts` walks the members), 180 KB of garbage and 5 ms on Dan's save. Count only what is drawn and leave the order to the next Resort. And the harness stub does not fire a child's `OnHide` when its parent hides, so the window calls each page's `release` itself rather than relying on it.
- **Popup titles sat under the frame border** (3.4.0.18): the popups' title was on the popup itself, below the Blizzard frame art's NineSlice (level about 500), so the metal edge cut it. Like the window's title (dev007), it now sits on a raised frame, in the title bar in Classic and Modern.
- **Ask which object a screenshot shows:** `/fstack` names only what is under the mouse; a screenshot of a highlighted region with an unrelated frame stack cannot be identified.
